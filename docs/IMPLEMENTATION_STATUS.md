## ما أصبح موجوداً ككود

### Android
- مشروع Gradle Wrapper 8.9، Kotlin 2.0.21، Android SDK 35، الحد الأدنى Android 8.
- تصميم عربي RTL بـ Compose، فاتح/داكن/حسب النظام، انتقال Fade + Slide، حركة رمز شاشة الدخول، حركة تقدم المهام، وتوسع العناصر، وحالات تحميل وفراغ وخطأ وتأكيد.
- الدخول، طلب التسجيل، عرض حالة عدم إتاحة الحساب، تغيير كلمة المرور، وإلزام الحساب المؤقت بالتغيير.
- إعداد اتصال Supabase داخل شاشة الدخول دون إعادة البناء، بمفتاح عام فقط. يرفض إدخال service-role JWT.
- حفظ الجلسة مشفراً بـ AES-GCM ومفتاح Android Keystore، وتجديد refresh token، وتسجيل الخروج خادمياً ومحلياً.
- مستودعات مصرح بها، تصفح وبحث وتحديد متعدد، قوائم خيارات الملفات، واختيار ملف/مجلد للتنزيل.
- اختيار عدة ملفات ومجلد SAF، حفظ إذن القراءة، والحفاظ على المسارات، وإنشاء المجلدات الفارغة بمهام مستقلة.
- تنزيلات ورفع عبر WorkManager، نتائج مستقلة، تقدم/حالة، وإلغاء وإعادة محاولة مع تراجع زمني للأخطاء المؤقتة.
- فك ZIP آمن بمجلد وجهة جديد وحدود عدد/حجم ومنع المسارات المطلقة وWindows و`..` والتكرار.
- Room لفهرس الملفات وسجل المهام. تصفح وبحث محلي وفتح الملفات عبر FileProvider. يختار المستخدم تنزيل النسخة الأحدث؛ لا يستبدل الفحص الخلفي الملفات.
- فحص نسخ الملفات عند عودة الشبكة وحالة الحذف البعيد، مع إبقاء الملفات المحلية عند فقد الصلاحية.
- شاشات إدارة الحسابات والموافقة والرفض وتعطيل الحساب وإعادة تعيين كلمة المرور ومنح/سحب الصلاحيات.
- ربط/تعطيل/إزالة ربط المستودعات، وشاشات سجل النشاط بالبحث والفلاتر والصفحات.

### Supabase / GitHub
- 3 هجرات SQL، RLS، منع الكتابة المباشرة للعميل، قيد مشرف واحد واسم المشرف المعتمد.
- موافقة تسجيل ذرية عبر RPC مقصورة على service-role.
- حسابات Auth ببريد اصطناعي؛ لا تُخزن كلمات مرور في جداول التطبيق.
- 11 Edge Function: auth-login، registration، account، repositories، files، downloads، uploads، admin-users، admin-repositories، admin-items، audit.
- فحص جلسة Auth وحالة الحساب والدور والصلاحيات خادمياً.
- HMAC لقيم مفاتيح تحديد معدل محاولات الدخول/التسجيل. وظيفة صيانة لحذف مفاتيح النوافذ القديمة.
- GitHub App JWT وinstallation token قصير العمر داخل الخادم فقط.
- رفع blobs وإجراء Git Tree/Commit وتحديث ref دون force، مع تحقق SHA قبل الاستبدال.
- نقل/إعادة تسمية/حذف محتوى المجلد كاملاً، وإضافة `.gitkeep` للمجلد الفارغ.
- تنزيل blob immutable محدد بـ SHA، وZIP streaming غير مضغوط يحافظ على المسارات، مع CRC وUTF-8.
- تسجيل بداية ونتيجة العمليات الحساسة، وعدم تسجيل مجرد تصفح الملفات أو كلمات المرور أو tokens.
- CI لفحص Android وDeno وSQL، وسكربت نشر بتأكيد المشروع، وسكربت bootstrap للمشرف دون حفظ كلمة المرور.

## حدود التنفيذ الحالية — ليست مكتملة وفق كل شروط الإنتاج
- رفع الملف محدود بـ **8 MiB**، وهو أقل من 90 MB المطلوبة أصلاً. لم يعتمد مسار رفع 90 MB.
- تنزيل الملف المفرد حتى 90 MiB وفك ZIP حتى 200 MiB في فحوصات الكود، لكن الأداء والذاكرة والمدة على Supabase المستضاف لم تُختبر فعلياً.
- ZIP حتى 1000 ملف، والشجرة حتى 10,000 مدخل. تُرفض الأشجار المبتورة وsymlink.
- مجموعة الرفع حتى 1000 عنصر و200 MiB من أحجام SAF المعلنة، مع حد فعلي لكل ملف أثناء البث.
- إدارة المستخدمين حتى 500 حساب، واكتشاف المستودعات أول 100 في الواجهة؛ يمكن ربط مستودعات أخرى بالاسم.
- المستودع الفارغ يحتاج commit أولياً عبر GitHub قبل عمليات Git Tree.
- التنزيل المستأنف يعيد المحاولة من البداية، وليس HTTP Range resume.
- نسبة التقدم قد تكون غير محددة عندما لا يقدم الخادم Content-Length؛ تظهر حالة نشاط بدلاً من نسبة تقديرية مضللة.
- نجاح سجل بث الخادم لا يؤكد الحفظ على الجهاز؛ نجاح/فشل الحفظ موجود في سجل المهام المحلي.
- سجل النشاط لديه صف started وصف نهائي منفصلان، وليسا سجل مهمة موزعاً يضمن exactly-once. تعطل الخادم بعد commit قد يترك العملية started دون خاتمة؛ يلزم فحص النسخة قبل إعادة عملية كتابة ملتبسة.
- يعتمد rate limiting لعناوين الشبكة على بوابة موثوقة تضبط forwarded-for، ويحتاج اختباراً عند النشر.

## ما لم يُنفذ على الخدمات أو الأجهزة
- لم تُطبّق الهجرات أو تُنشر الوظائف على مشروع Supabase للمستخدم.
- لم تُقرأ مفاتيح مشروع `unihub1` ولم تُغيّر إعداداته؛ يلزم تأكيد أنه المشروع المقصود.
- لم يُنشأ حساب مشرف فعلي أو GitHub App أو حسابات مستخدمين حقيقية.
- لا يوجد GitHub App secret داخل APK أو الملفات. المفتاح العام وURL يُضبطان عند الإعداد.
- لم تُرفع التغييرات إلى GitHub.
- لم تُجر اختبارات UI/Instrumentation على جهاز أو محاكي Android، ولا اختبارات تكامل حقيقية ضد Supabase/GitHub أو حمل/انقطاع أثناء نقل كبير.
- لم تُجهز مفاتيح توقيع إصدار الإنتاج أو نشر متجر؛ APK المرفق Debug للتجربة.

النتيجة: تنفيذ واسع للواجهات والمسارات الخلفية مع بناء واختبارات محلية، **وليس تصريحاً بأن كل سيناريو جاهز للإنتاج**. راجع SETUP.md قبل ربط خدمات فعلية.

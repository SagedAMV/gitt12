# عقود Edge Functions — v0.2

كل الطلبات `POST`. البيانات JSON باستثناء `uploads` (جسم ثنائي). الأخطاء JSON بصيغة `{ "error": "message" }` مع حالة HTTP. Android يترجم الأخطاء الشائعة إلى العربية. جميع الوظائف المحمية تحتاج `Authorization: Bearer <access_token>`؛ الدور وحالة الحساب والصلاحيات تُستخرج من الخادم، ولا تؤخذ من جسم الطلب.

## عامة
| الوظيفة | الجسم | النتيجة |
|---|---|---|
| `auth-login` | `username`, `password` | `session`, `profile` للحساب ACTIVE فقط، وإمكانية إلزام تغيير كلمة المرور |
| `registration` | `username`, `password` | `status=PENDING` دون جلسة؛ كلمة المرور تُرسل إلى Auth فقط |
| `account` action=`refresh` | `refresh_token` | جلسة متجددة وprofile، بعد فحص ACTIVE |

اسم المستخدم: `[a-z0-9_]{3,32}`. Android يحول الاسم إلى أحرف صغيرة. كلمات المرور الجديدة 12–128 حرفاً. لا تُحفظ في جداول التطبيق أو السجلات. الدخول والتسجيل محدودان بـ10 محاولات لكل اسم ولكل عنوان بوابة خلال 15 دقيقة، باستخدام HMAC قبل التخزين. هذا حد أولي يحتاج ضبطاً واختباراً خلف بوابة الاستضافة.

## حساب مصادق
- `account`: action=`me` → `profile`.
- `account`: action=`password`, `current_password`, `password` → إعادة مصادقة بكلمة المرور الحالية، ثم تحديث وإزالة علامة المؤقتة وإبطال جلسات refresh. على Android تسجيل الدخول مجدداً.
- `account`: action=`logout` → إبطال الجلسة الحالية لدى Auth. JWT الذي صدر سابقاً قد يبقى صالحاً حتى انتهاء مدته حسب سلوك Supabase؛ تعطيل الحساب أو سحب صلاحية المستودع يُفحصان من قاعدة البيانات في كل طلب جديد.
- الحساب ذو `must_change_password=true` لا يستعمل إلا مسارات الحساب السابقة حتى التغيير.

## قراءة المستودعات والملفات
- `repositories`: `{}` → `repositories[]`، المصرح بها والنشطة فقط.
- `files`: `repository_id`, `path` (الجذر `""`) → `items[]` مع name/path/type/size/sha. يُقرأ snapshot محدد للشجرة مع رفض الشجرة المبتورة أو الأكبر من 10,000 مدخل.
- `files`: `repository_id`, action=`versions`, و`ref` اختياري كـSHA commit من 40 خانة → قاموس `versions` من path إلى blob SHA، لدعم فحص النسخ المحلية وفهرسة ZIP.
- `downloads`: `repository_id`, `paths[]`, `format`=`file` أو `zip`.
  - file: مسار واحد لملف واحد فقط؛ الاستجابة octet-stream و`X-Vault-Sha` هو blob SHA.
  - zip: ملف/مجلد/مجموعة؛ `X-Vault-Sha` هو commit SHA. الأسماء نسبية من جذر المستودع، مع إزالة العناصر المكررة بسبب تداخل اختيار المجلدات.
  - ملفات symlink غير مدعومة. ZIP حتى 1000 ملف و200 MiB غير مضغوط. فحص أقصى 90 MiB للملف في الخادم ليس اعتماداً لقدرة النقل الفعلية.
  - تُفحص الجلسة والصلاحيات عند الطلب وقبل كل blob stream. سحب الصلاحية أثناء بث blob بدأ بالفعل لا يضمن استرجاع البايتات التي أُرسلت.
  - تُسجل بداية التنزيل ونهاية بث الخادم أو فشله. نجاح البث ليس إثباتاً بأن Android حفظ البيانات نهائياً؛ نتيجة الحفظ المحلي في سجل المهام المحلي.

## إدارة الحسابات — ADMIN
`admin-users`:
- action=`list`: `users[]`, `requests[]`, `access[]` (حتى 500 مستخدم في الواجهة الحالية).
- action=`create`: `username`, `password` → حساب ACTIVE بكلمة مرور مؤقتة.
- action=`review`: `user_id`, `approve` boolean → موافقة/رفض ذري في SQL؛ لا يقبل القرار مرتين.
- action=`status`: `user_id`, `status`=`ACTIVE`/`DISABLED` للحسابات المراجعة فقط.
- action=`reset`: `user_id`, `password` → يفرض كلمة مرور مؤقتة جديدة.
- action=`grant`/`revoke`: `user_id`, `repository_id`.
- لا يجوز تعديل حساب المشرف بهذه العمليات.

## إدارة المستودعات — ADMIN
`admin-repositories`:
- action=`list`: جميع المستودعات المدارة بما فيها المعطلة.
- action=`available`, `page` اختياري: مستودعات GitHub App التابعة للمالك المسموح، 100 في الصفحة.
- action=`link`, `name`: يتحقق من GitHub ويربط/يفعّل المستودع في قاعدة البيانات.
- action=`status`, `repository_id`, `active` boolean.
- action=`unlink`, `repository_id`: يحذف الربط والصلاحيات المرتبطة فقط. لا يرسل حذف مستودع إلى GitHub.

## إدارة المحتوى — ADMIN
- `admin-items`: `repository_id`, action=`mkdir`, `path` → ينشئ `.gitkeep`.
- `admin-items`: `repository_id`, action=`move`, `path`, `destination` → ملف أو كل محتوى مجلد؛ يشمل إعادة التسمية. يرفض الوجهة الموجودة أو نقل المجلد داخل نفسه.
- `admin-items`: `repository_id`, action=`delete`, `path` → يزيل النسخة الحالية دون مسح التاريخ.
- العمليات مبنية على Git Tree + Commit + تحديث ref دون force، وترفض تعارض الكتابة بدلاً من الكتابة فوق تعديل متزامن.
- نقل/حذف حتى 1000 blob في العملية. المستودع الفارغ كلياً يحتاج commit أولياً قبل استخدام إدارة المحتوى.

`uploads?repository_id=<uuid>&path=<encoded-path>`:
- الجسم binary، الحد 8 MiB لكل ملف. هذا قيد تنفيذ حالي وليس الحد الأصلي المطلوب 90 MB.
- عند استبدال ملف يجب إرسال `x-expected-sha` مطابقاً للنسخة الحالية؛ وإلا 409. Android يطلب تأكيد المستخدم قبل إدراج مجموعة الرفع.
- الملفات ترفع بمهام مستقلة؛ فشل ملف لا يلغي الملفات التي نجحت.
- مجلدات SAF الفارغة تُضاف كمهام إنشاء مجلد، والمجلدات غير الفارغة تُجزأ إلى ملفات مع الحفاظ على المسارات.

## سجل النشاط — ADMIN
`audit`: `offset` (افتراضي 0، صفحة 50)، `action` نص بحث اختياري، `outcome`=`started`/`success`/`failed`/`pending` → `logs[]`, `offset`.

سجل الخادم غير قابل للكتابة من العميل عبر PostgREST. لا يُسجل تصفح المجلدات. تغيير كلمات المرور لا يسجل كلمة المرور نفسها. لا تتضمن الاستجابات GitHub tokens أو مفاتيح الخادم.

## حالات HTTP
- 400 بيانات/مسار غير صالح.
- 401 جلسة أو بيانات دخول غير صالحة.
- 403 دور/حالة حساب/إلزام تغيير كلمة المرور.
- 404 عنصر غير متاح؛ تُستخدم أيضاً لمنع كشف المستودعات غير المصرح بها.
- 409 تعارض محتوى أو وجهة موجودة.
- 413 تجاوز حدود حجم/عدد.
- 429 حد محاولات.
- 500 خطأ داخلي دون تسريب تفاصيل حساسة.
- 502 تعذر إكمال GitHub request.

# عمليات المجلدات الكاملة في مستودعات saged7 — التصميم والمبررات

الإصدار 1.0.0 (versionCode 12) — أبرز إضافة منذ 0.9.1.

## ما الجديد

التحكم الكامل بمحتوى مستودعات GitHub كأنه مجلد عمل عادي:

| العملية | كيف تنفذ |
|---|---|
| تحديد متعدد | ضغط مطوّل على أي صف، ثم لمس إضافي للأصفار الأخرى |
| نسخ / قص | أزرار شريط التحديد؛ القص يمسح المصدر عند اللصق |
| لصق | شريط الحافظة العائم؛ داخل نفس المجلد أو مجلد آخر أو **مستودع آخر** |
| تسمية | ملف واحد أو مجلد كامل (ينقل كل ملفات تحته) |
| مسح | ملف أو مجلد بالكامل من شجرة git |
| مجلد جديد | عبر `.gitkeep` لأن git لا يعرف المجلدات الفارغة |
| تابع التنفيذ | كل عمليات الشجرة في طابور «الشغل» مع تقدم حي وزر وقف وإعادة |

## لماذا هذه البنية بدل البدائل؟

**1. مخطط نقي (FileOps) منفصل عن الشبكة والواجهة.**
البديل كان كتابة المنطق مباشرة في ViewModel أو الـ worker. اخترنا الدوال النقية لأنها تُختبر على JVM بلا شبكة ولا محاكي أندرويد (ومحاكي Robolectric لا يتحرك أصلاً تحت حد الكومة 64MiB المفروض في هذا المشروع — انظر StreamingUploadTest)، ولأن القرارات الحساسة (تنافر الأسماء، تفكيك المجلدات، حدود العمليات) تصير قابلة للمراجعة في ملف واحد.

**2. الطابور (WorkManager + جدول transfers) بدل التنفيذ الفوري.**
البديل كان تنفيذ العمليات لحظياً من الواجهة. العمليات الواحدة قد تكون عشرات نداءات GitHub (مسح مجلد = commit لكل ملف)، والنت في هذا التطبيق يُعامل كمورد غير مضمون. الطابور يعطي: تقدماً معروضاً، إلغاءً وإعادة، وبقاء الشغل بعد قتل التطبيق — نفس فلسفة الرفع والتنزيل الموجودة أصلاً.

**3. Contents API بعمليات متتالية بدل Git Data API بـ commit واحد.**
البديل كان تركيب شجرة جديدة (blobs → tree → commit → تحديث المرجع) في نداء واحد. رُفض لثلاثة أسباب: يتطلب تحميل كل محتوى للذاكرة (التطبيق مقيّد بـ 90MiB وذاكرة معدة للكومة الصغيرة)، يفقد منطق التقدم التدريجي الذي يظهر في «الشغل»، ويضاعف تعقيد إعادة المحاولة. المقابل: كل ملف commit مستقل، والتقدم حقيقي خطوة بخطوة، والحد 400 عملية يحمي من استهلاك حصة الطلبات.

**4. جعل PUT «upsert» بجلب sha الحالي قبل الكتابة.**
البديل كان إعادة التشغيل من أول العملية عند الفشل الجزئي، فتفشل الخطوات المنفذة سابقاً بـ 422. جلب sha الموجود أولاً يجعل كل خطوة idempotent، ويضيف قفزة ذكية: إذا كان sha الهدف مطابقاً للمصدر فتُتخطى الخطوة كلها — إعادة المحاولة بعد انقطاع النت تصير شبه مجانية.

**5. الحافظة عبر العناصر (repo, path, type, sha) بدل نظام الحافظة العام لنظام أندرويد.**
نظام النظام يحمل نصوصاً وصوراً ولا يحمل shas ومستودعات المصدر. حافظة خاصة داخل التطبيق تحمل كل ما يلزم للصق عبر المستودعات.

**6. ضغط مطوّل للتحديد بدل قوائم لكل صف.**
قائمة خيارات لكل صف تعني 4 أيقونات × عدد الصفوف وشاشة مزدحمة على 360dp. الضغط المطوّل يحرر المساحة ويوحّد سلوك الملفات والمجلدات، مع شريط إجراءات واحد ظاهر فقط عند الحاجة.

## لماذا هذه الاختبارات تحديداً؟

| الاختبار | ماذا يثبت | لماذا هو الشكل المناسب |
|---|---|---|
| `FileOpsTest` (17 حالة) | بنية الخطوات المولدة: حفظ بنية المجلدات، تنافر الأسماء `report (1).pdf`، أزواج القص PUT+DELETE، تفكيك المجلد من شجرة git، حدود 400 عملية، تقريب JSON round-trip | المنطق كله هنا؛ اختبار نقي يمر في أجزاء الثانية تحت 64MiB |
| `TreeOpRunnerTest` (10 حالات) | الترتيب SHA→BLOB→PUT→DEL، قفزة المحتوى المطابق عند إعادة المحاولة، ملف .gitkeep فاضي، توقف السلسلة عند أول فشل، تقدم متقدم، تنظيف الملفات المؤقتة، رفض sha الناقص | API مزوّر يسجل النداءات يثبت «الترتيب والتزامن» دون لمس شبكة حقيقية |
| `GitHubPolicyTest.singleSegmentNames` | رفض `/` و`\` و`:` و`..` والأسماء الفارغة والطويلة | مسارات المستخدم تصل GitHub مباشرة؛ الفلترة عند الباب |
| `SimpleCopyTest.treeOpsCopyIsPoliced` | رسائل الإضافة الجديدة قصيرة ومُعتمدة ومصنفة صح/خطأ/انتظار | نظام النسخ في هذا المشروع مُراقب باختبار؛ الإضافة التزمت بنفس المقياس |

ما لم يُختبِرناه عمداً: نداءات HTTP الفعلية (تغطيها واجهة GitHub الرسمية + StreamingUploadTest للبروتوكول)، واللقطات البصرية (DesignScreenshotTest يظل يعمل دون تعديل لأن الوسائط الجديدة للواجهة لها قيم افتراضية).

## الحركة

- دخول الصفوف متدرج (28ms لكل صف، سقف 336ms) مرة واحدة لكل فتح مجلد، ويتوقف كلياً عندما تكون أنميشنات النظام معطلة (`ValueAnimator.areAnimatorsEnabled`) — نفس احترام VisualPolicy.
- علامة التحديد تنبض بنابض (damping 0.52) وتلون الصف بـ animateColorAsState.
- شريطا التحديد والحافظة يطلعان بانزلاق نابض وانكماش عمودي، لا يحجزان القائمة ولا يظهران إلا عند الحاجة.
- كل ضغط يمر عبر نظام Motion الموجود (انكماش 0.965 بنابض) فبقيت اللغة البصرية واحدة.

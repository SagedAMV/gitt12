# GitHub Vault --- نطاق التطبيق

## 1. الغرض من هذا المستند

يحدد هذا المستند ما الذي يدخل ضمن مسؤولية GitHub Vault وما الذي لا يدخل
فيها، لتقليل الالتباس أثناء التصميم والتنفيذ والاختبار.

## 2. المنصة التقنية المعتمدة

- Android Native باستخدام Kotlin.
- Supabase Auth للمصادقة وإدارة الجلسات.
- Supabase PostgreSQL لبيانات المستخدمين والصلاحيات والمستودعات وسجل النشاط.
- Supabase Edge Functions للتحقق من الصلاحيات وتنفيذ العمليات الحساسة على GitHub.
- GitHub لتخزين المستودعات والملفات وتاريخ الإصدارات.
- لا يتطلب الإصدار الأول خادماً خاصاً أو Backend مستقلاً.

## 3. الأدوار

### Admin

يوجد مشرف واحد فقط في النظام. يمتلك صلاحيات إدارة المستودعات والمستخدمين
والصلاحيات والملفات والمجلدات ومراجعة سجل النشاط.

### User

المستخدم العادي. يستطيع رؤية المستودعات التي خصصها له المشرف، وتصفحها
وتنزيل محتوياتها. لا يملك صلاحيات كتابة إلى GitHub.

## 4. الوظائف التي ينفذها التطبيق

### 4.1 الحسابات والدخول

-   تسجيل الدخول باسم المستخدم وكلمة المرور.
-   إنشاء حساب بواسطة المشرف؛ ويحدد المشرف كلمة مرور مؤقتة تُلزم
    المستخدم بالتغيير عند أول تسجيل دخول.
-   استقبال طلب تسجيل ذاتي يحدد فيه المستخدم اسم المستخدم وكلمة المرور،
    ويبقى الطلب منتظراً موافقة المشرف. بعد الموافقة يستخدم المستخدم
    كلمة المرور التي اختارها.
-   قبول أو رفض طلب التسجيل بواسطة المشرف.
-   منع الحساب غير الموافق عليه أو المعطل من الوصول.
-   السماح للمستخدم بتغيير كلمة مروره بعد تسجيل الدخول.
-   السماح للمشرف بإعادة تعيين كلمة المرور وفق إجراء آمن.
-   لا يتطلب التطبيق بريداً إلكترونياً من المستخدم في تجربة الدخول
    المعتمدة.

### 4.2 إدارة المستخدمين --- Admin

-   عرض المستخدمين والبحث عنهم.
-   إنشاء حساب مستخدم.
-   تفعيل الحساب أو تعطيله.
-   مراجعة طلبات التسجيل.
-   منح المستخدم صلاحية الوصول إلى مستودعات محددة أو سحبها.
-   مراجعة نشاط المستخدمين.

### 4.3 إدارة المستودعات --- Admin

-   إضافة مستودع من حساب GitHub المرتبط.
-   عرض المستودعات التي يديرها النظام.
-   تفعيل المستودع أو تعطيله داخل التطبيق.
-   إزالة ربط مستودع من النظام وفق سياسة واضحة.
-   تخصيص كل مستودع لمستخدم أو أكثر.

إزالة الربط من التطبيق تسحب وصول GitHub Vault والمستخدمين إلى المستودع،
ولا تحذف المستودع الأصلي أو ملفاته من حساب GitHub. لا تتضمن النسخة الأولى
عملية حذف المستودع الأصلي من GitHub.

### 4.4 إدارة الملفات والمجلدات --- Admin

-   استعراض شجرة المستودع.
-   رفع ملف منفرد.
-   رفع عدة ملفات.
-   رفع مجلد كامل.
-   رفع عدة مجلدات.
-   إنشاء مجلد؛ وإذا كان فارغاً، ينشئ التطبيق ملف `.gitkeep` داخله
    ليظهر المجلد في GitHub.
-   إعادة تسمية ملف أو مجلد.
-   نقل ملف أو مجلد؛ نقل المجلد أو إعادة تسميته يشمل جميع محتوياته
    ومجلداته الفرعية.
-   حذف ملف أو مجلد.
-   إظهار تقدم ونتيجة كل عملية رفع بصورة مستقلة.
-   فشل رفع ملف لا يلغي الملفات التي نجح رفعها؛ يمكن إعادة محاولة
    الملفات الفاشلة فقط.
-   الحفاظ على المسارات النسبية والأسماء عند الرفع.
-   الحد الأقصى لحجم الملف الواحد 90 MB في الإصدار الأول؛ تُرفض الملفات
    الأكبر ولا يدعم الإصدار الأول Git LFS.
-   حذف الملفات أو المجلدات يزيلها من النسخة الحالية للمستودع مع
    الاحتفاظ بها في تاريخ Git وإمكانية استعادتها.

تُنفذ هذه العمليات على GitHub من خلال Supabase Edge Functions فقط بعد التحقق من جلسة المستخدم ودور Admin وصلاحية المستودع.

### 4.5 تصفح وتنزيل الملفات --- User

-   عرض المستودعات المصرح بها فقط.
-   تصفح المجلدات والملفات.
-   تنزيل ملف منفرد بصيغته الأصلية.
-   تحديد عدة ملفات وتنزيلها في أرشيف ZIP واحد.
-   تنزيل مجلد كامل في ZIP مع الحفاظ على هيكل المجلدات.
-   تنزيل مجموعة مختارة من الملفات والمجلدات.
-   عرض تقدم التنزيل وحالته.
-   إعادة محاولة التنزيل الفاشل.
-   فك ZIP بعد التنزيل وعرض المحتويات كبنية مجلدات طبيعية.
-   فتح الملفات باستخدام التطبيقات المناسبة المثبتة على الجهاز، عندما
    يدعم Android ذلك.

### 4.6 العمل دون اتصال

-   عرض قائمة الملفات التي سبق تنزيلها واكتمل حفظها.
-   تصفح المجلدات المحلية.
-   فتح الملفات المحلية.
-   البحث ضمن الفهرس المحلي للملفات المنزّلة إذا تم تضمين البحث في النسخة
    الأولى.
-   توضيح أن المحتوى المحلي قد لا يعكس أحدث نسخة في GitHub.
-   عند اكتشاف نسخة أحدث من ملف، يُنبّه التطبيق المستخدم ويتيح تنزيلها؛
    ولا يستبدل النسخة القديمة إلا باختيار المستخدم.
-   إذا حذف المشرف ملفاً من النسخة الحالية في GitHub، تبقى النسخة
    المحلية ظاهرة مع إشارة إلى أنه حُذف من المستودع.
-   تبقى الملفات المحلية بعد سحب الصلاحية أو تعطيل الحساب أو حذف الملف
    من GitHub؛ ولا يحذفها التطبيق تلقائياً.
-   تحفظ الملفات المنزّلة داخل مساحة التطبيق الخاصة على Android.
-   تحديث البيانات من الخادم عند عودة الاتصال.

### 4.7 سجل النشاط --- Admin

يسجل النظام:
- محاولات تسجيل الدخول ونتائجها.
- طلبات التسجيل والموافقة والرفض.
- تغييرات الحسابات والصلاحيات.
- تنزيل الملفات والمجلدات ونتائجها.
- عمليات ربط المستودعات أو تعطيلها أو إزالة ربطها.
- رفع الملفات والمجلدات، مع نتيجة كل عملية مستقلة.
- إنشاء المجلدات وإعادة تسميتها ونقلها وحذفها.
- وقت العملية والفاعل والهدف والنتيجة.

لا يسجل النظام مجرد تصفح الملفات أو عرض أسماء المجلدات.

يستطيع المشرف الاطلاع على السجل والبحث والتصفية فيه. لا يستطيع المستخدم
العادي الاطلاع عليه أو تعديله.

## 5. الوظائف التي لا ينفذها التطبيق

-   لا يسمح للمستخدم العادي برفع أو تعديل أو حذف ملفات GitHub.
-   لا يسمح للمستخدم العادي بإنشاء مستودعات أو تغيير إعداداتها.
-   لا يسمح للمستخدم العادي بتغيير صلاحياته أو صلاحيات الآخرين.
-   لا يعرض مستودعات غير مخصصة للمستخدم.
-   لا يتصل Android مباشرة بـ GitHub باستخدام مفاتيح إدارية؛ تمر العمليات الحساسة عبر Supabase Edge Functions.
-   لا يخزن GitHub tokens أو private keys أو Supabase service-role key داخل APK.
-   لا يجعل الملفات المحلية تعديلات تلقائية على GitHub.
-   لا يوفر مزامنة ثنائية الاتجاه لتعديلات الملفات.
-   لا يعمل على جلب ملفات جديدة من GitHub دون إنترنت.
-   لا يعد بفتح كل أنواع الملفات بنفسه؛ قد يستعين بتطبيق خارجي مناسب.
-   لا يعد باستعادة كلمة المرور ذاتياً عبر البريد الإلكتروني في غياب بريد
    مسجل؛ إعادة التعيين تتم عبر المشرف.
-   لا يحرر محتوى ملفات Word أو Excel أو PDF أو الفيديو داخل التطبيق في
    النطاق الأولي.
-   لا يدعم Git LFS في الإصدار الأول، ويرفض الملفات التي تتجاوز 90 MB.
-   لا يدعم حسابات GitHub متعددة أو مستودعات من ملاك مختلفين في النسخة
    الأولى.
-   لا يضمن أن GitHub مناسب بلا قيود لكل أحجام الفيديو أو الملفات
    الثنائية؛ يجب احترام حدود GitHub وGit LFS والخطة.

  العملية                                                     Admin                 User
  --------------------------------------- ------------------------- --------------------
  تسجيل الدخول                                                  نعم                  نعم
  تغيير كلمة المرور                                             نعم                  نعم
  طلب تسجيل ذاتي                                          غير مطلوب                  نعم
  الموافقة على طلبات التسجيل                                    نعم                   لا
  إنشاء المستخدمين وإدارتهم                                     نعم                   لا
  إضافة مستودع                                                  نعم                   لا
  تحديد صلاحيات المستودعات                                      نعم                   لا

  تصفح الملفات                                                  نعم   نعم، ضمن المصرح به
  تنزيل الملفات                                                 نعم                  نعم

  إنشاء/تعديل/نقل/حذف الملفات والمجلدات                         نعم                   لا
  عرض سجل النشاط                                                نعم                   لا

## 7. متطلبات غير وظيفية

-   أمان النقل عبر HTTPS.
-   تحقق من الصلاحيات في Supabase Edge Functions وRLS لكل عملية.
-   يتولى Supabase Auth تخزين كلمات المرور والتحقق منها؛ لا تخزن جداول التطبيق كلمات المرور أو تجزئاتها.
-   استجابة مناسبة للأخطاء وانقطاع الشبكة.
-   واجهة عربية قابلة لدعم لغات إضافية لاحقاً.
-   دعم تخزين الملفات المحلية والعمل دون اتصال للمحتوى المنزّل.
-   تسجيل العمليات الحساسة.
-   استخدام Supabase Auth وPostgreSQL وEdge Functions دون خادم Backend مستقل في الإصدار الأول.
-   مراعاة إمكانية الوصول وحالات التحميل والفراغ والفشل.

## 8. شروط القبول الأساسية

1.  المستخدم غير الموافق عليه لا يستطيع تسجيل الدخول أو الوصول إلى
    المستودعات.
2.  المستخدم لا يرى إلا المستودعات المخصصة له.
3.  محاولة User استدعاء وظيفة إدارية مباشرة تُرفض من Edge Function وRLS.
4.  Admin يستطيع إضافة مستودع وإدارته ضمن حساب GitHub المعتمد.
5.  Admin يستطيع رفع ملف ومجلد مع الحفاظ على المسارات.
6.  User يستطيع تنزيل ملف منفرد ومجموعة ومجلد.
7.  الأرشيف المستخرج لا يسمح بكتابة ملفات خارج مجلد الوجهة.
8.  الملفات المنزّلة متاحة للتصفح دون اتصال.
9.  كل عملية إدارية وتنزيل مهمة تظهر في سجل النشاط بنتيجة صحيحة.
10. لا يوجد أي GitHub secret أو Supabase service-role key داخل تطبيق Android أو في سجلاته.

## 9. قرارات معتمدة وحدود ما زالت تحتاج تفصيلاً

### قرارات معتمدة
-   المستودعات ضمن حساب GitHub شخصي واحد مخصص بالكامل للتطبيق؛ ويصل
    GitHub App إلى جميع مستودعات هذا الحساب.
-   يوجد مشرف واحد فقط.
-   الحد الأقصى للملف الواحد 90 MB، ولا يدعم الإصدار الأول Git LFS.
-   تحفظ الملفات المنزّلة داخل مساحة التطبيق الخاصة.
-   تبقى النسخ المحلية بعد سحب الصلاحية أو تعطيل الحساب أو حذف الملف
    من GitHub.
-   حذف الملف من GitHub يزيله من النسخة الحالية مع الاحتفاظ بتاريخ Git.
-   إزالة ربط المستودع لا تحذف المستودع الأصلي.
-   المجلدات الفارغة تُمثّل بملف `.gitkeep`.
-   نقل المجلد أو إعادة تسميته يشمل جميع محتوياته.
-   عمليات الرفع مستقلة، وفشل عنصر لا يلغي نجاح العناصر الأخرى.
-   تحديث الملف لا يستبدل النسخة المحلية إلا بموافقة المستخدم.
-   سجل النشاط لا يتضمن مجرد تصفح الملفات والمجلدات.

### تفاصيل ما زالت تحتاج تحديداً قبل التنفيذ
-   الحد الأقصى لحجم مجموعة الرفع وZIP وعدد الملفات في العملية الواحدة.
-   طريقة اختيار الملفات والمجلدات من Android وفق قيود نظام التشغيل.
-   قواعد اسم المستخدم وحدود محاولات الدخول.
-   آلية التهيئة الآمنة لإنشاء حساب المشرف الأول في Supabase Auth ومنع إنشاء Admin ثانٍ.
-   اختبار عملي لمسار رفع وتنزيل الملفات حتى 90 MB مع حدود Supabase Edge Functions، أو اعتماد وسيط نقل إضافي/تخفيض الحد إذا لم ينجح الاختبار.

# وضع saged7 العام — الإصدار 0.4.0

## الاختيار المعتمد من المالك
- قراءة المستودعات العامة فقط للحساب `https://github.com/saged7`.
- توكن الرفع اختياري، ومحفوظ على الجهاز وليس في Supabase.
- هذا استثناء معتمد من المعمارية السابقة: عمليات هذا الوضع تتصل مباشرة بـ GitHub، وليست عبر GitHub App أو Edge Functions. تبقى أدوات إدارة السحابة السابقة منفصلة.

## الاستخدام
1. ثبّت APK 0.4.0. تفتح شاشة `saged7` تلقائياً دون تسجيل دخول.
2. اختر مستودعاً لعرض مجلداته وملفاته. البحث داخل القوائم المعروضة محلي.
3. اضغط الملف للمعاينة النصية المحدودة، أو تنزيله؛ تظهر نتيجة التنزيل في المهام والملف المكتمل في المحفوظات.
4. للرفع، اضغط **توكنك**، ثم ألصق Personal Access Token داخل التطبيق واضغط **احفظه**.
5. افتح المجلد المطلوب واضغط رفع ملفات؛ تُعرض نافذة تأكيد قبل إدراج المهام. الملفات المتطابقة بالاسم قد تُستبدل بشرط مطابقة SHA الذي عُرض وقت الاختيار.
6. راقب المهام وحدّث المجلد بعد نجاح الرفع. يوجد إلغاء وإعادة محاولة. كل ملف عملية مستقلة.

## توكن GitHub
- الأفضل Fine-grained personal access token بمالك الموارد `saged7`، ومحدد بالمستودعات المطلوبة فقط، مع **Contents: Read and write** ومدة انتهاء محدودة.
- يجب أن تكون لك صلاحية الكتابة فعلياً؛ لا يمنح التطبيق حقوقاً ليست في التوكن أو حساب GitHub.
- القراءة العامة لا تستخدم التوكن، حتى إن كان محفوظاً. التوكن يُرسل إلى `api.github.com` فقط للتحقق من صاحبه أو صلاحية المستودع أو تنفيذ الرفع.
- يُحفظ AES-GCM في مساحة التطبيق الخاصة بمفتاح Android Keystore منفصل عن مفتاح جلسة Supabase.
- لا يُكتب في السورس أو WorkManager input أو Room أو ملفات التسليم أو سجلات الشبكة، ولا يُرسل إلى Supabase.
- لا تُتبع إعادة التوجيه في عميل GitHub، لمنع تحويل طلب يحتوي على Authorization إلى وجهة أخرى.
- من نافذة التوكن يمكنك استبداله أو حذفه. الحذف يلغي مهام الرفع المحلية ويطلب إلغاء الطلبات المصادقة الجارية؛ لا يمكنه التراجع عن commit اكتمل بالفعل.
- الإلغاء النهائي لصلاحية التوكن يتم من إعدادات GitHub، وليس بمجرد حذفه من الهاتف.
- تسجيل الخروج من حساب Supabase منفصل عن هذا التوكن المحلي. احذفه صراحةً من نافذة توكن الرفع إذا أردت إزالته.
- لا تلصق التوكن في المحادثة.

## الحدود الحالية
- المستودعات الخاصة لا تظهر ولا تُقرأ في هذا الوضع، والرفع يرفض المستودع إن لم يكن عاماً ومملوكاً لـ saged7.
- لا يُستخدم حساب `SagedAMV` كمصدر الملفات لهذا الوضع؛ حساب الهدف ثابت `saged7`.
- قائمة المستودعات 100 في الصفحة مع زر تحميل المزيد.
- عرض المجلد عبر Contents API؛ إذا بلغت القائمة 1000 عنصر تُرفض بدلاً من عرض قائمة قد تكون مبتورة.
- معاينة نصية فقط حتى 512 KiB؛ لا تُنفذ HTML أو JavaScript، ولا يعد التطبيق بمعاينة الملفات الثنائية. التنزيل والفتح الخارجي متاحان للملفات المكتملة.
- التنزيل حتى 90 MiB للملف في فحص الكود، والرفع حتى 90 MiB للملف و100 ملف في عملية اختيار. اختُبر مسار الطلب HTTP محلياً بملف 90 MiB وبذاكرة JVM قدرها 64 MiB؛ لم يُختبر على هاتف فعلي أو مع GitHub حقيقي.
- لا يوجد تنزيل ZIP جماعي أو اختيار مجلد كامل للرفع في وضع GitHub المباشر الجديد. هذه الخيارات تبقى ضمن المسار السابق المدعوم بالخادم إذا أُعدّ GitHub App.
- يتبع التصفح حدود GitHub API غير المصادق، عادةً 60 طلباً في الساعة لكل عنوان IP. تُعرض رسالة عند استنفاد الحد.
- تبقى الملفات المنزلة متاحة محلياً. فحص التحديثات لا يستبدل النسخة الحالية تلقائياً.
- بيانات القوائم ليست مخبأة كتصفح كامل دون اتصال؛ العمل دون الاتصال للملفات التي اكتمل تنزيلها فقط.

## تحقق فعلي للحساب
في 11 نوفمبر 2026، استُخدمت طلبات GitHub العامة فقط دون Authorization:
- نجح عرض مستودعين عامين: `sageer` و`-`.
- أعاد GitHub `size=0` و`default_branch=main` لكليهما، و404 لمسار Contents؛ عولجت الحالة في الكود بوصفها مستودعاً فارغاً بعد تأكيد أنه عام وحجمه صفر.
- لم يُنشأ أو يُعدّل أو يُرفع أي ملف في الحساب.
- لا يوجد توكن متاح للمساعد؛ لذلك لم يُختبر رفع حقيقي أو تحقق صلاحية توكن المستخدم.

## البناء والاختبارات
- نجح compileDebugKotlin وassembleDebug وlintDebug.
- نجح 22 اختبار JUnit: 10 لاستخراج ZIP، و8 للسياسة، و3 للبث والنقل وحد الحجم، واختبار لقصر رسائل الأخطاء.
- تبقى تجربة الواجهة والـKeystore وSAF وWorkManager والرفع على جهاز Android فعلي مطلوبة. هذه نسخة تطوير Debug وليست اعتماداً للإنتاج.

## السحابة
لم تُنفذ أي تعديلات سحابية لإضافة هذا الوضع. إعداد مشروع GitHub Vault الجديد وحساب المشرف السابق محفوظان كما هما. لم يُستخدم المشروع الآخر المحظور.

## إنشاء مستودع
من القائمة اضغط **مستودع جديد**، اكتب الاسم، ثم **سوّه**. يُنشأ مستودع **عام** في حساب saged7 مع README أولي. لا ينشئ التطبيق مستودعات في حساب صاحب توكن آخر. يحتاج التوكن إلى Administration: Read and write بالإضافة إلى Contents للرفع. اختر الوصول الملائم للمستودعات الجديدة في إعداد GitHub؛ قد تحتاج تحديث نطاق التوكن بعد الإنشاء إذا كان مقيداً بمستودعات مختارة. فشل الإذن لا يؤدي إلى إرسال الطلب بحساب بديل.

## واجهة 0.4.0
التبويبات الأساسية أربعة: saged7، عندك، الشغل، حسابك. انتقل إلى المسار السحابي القديم من حسابك ثم إدارة السحابة بعد الدخول. اختُصرت الأزرار والرسائل إلى تعبيرات عامية قصيرة؛ النصوص الشارحة والتحذيرات التفصيلية داخل حوارات التأكيد ليست أسماء إجراءات. أخطاء الشبكة والخادم لا تعرض stack trace أو نصوصاً طويلة للمستخدم.

## نقل كبير
يُنسخ ملف SAF إلى ملف مؤقت محدود الحجم، ثم يُبث Base64 إلى جسم طلب Contents مباشرة بذاكرة ثابتة تقريباً، دون ByteArray للملف أو JSON كامل بالذاكرة. يُحذف المؤقت بعد النجاح أو الفشل. يدعم إشعار نقل أمامي وعداد تقدم؛ لا يدعم استكمال ملف جزئي، وإعادة المحاولة تبدأ الملف من جديد. GitHub قد يرفض الكتابة بسبب الصلاحيات أو حماية الفرع أو سياسة المستودع. لا توجد صلاحية لرفع ملف اختبار إلى الحساب من جلسة التطوير.
